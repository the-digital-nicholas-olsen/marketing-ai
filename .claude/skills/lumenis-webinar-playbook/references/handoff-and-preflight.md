# Hand-off (C12) and pre-flight (L1)

## C12 Landing page hand-off (Ted to operations, around T-33)

Everything operations needs to finish the ON24 page, in one message, after the KOL approves the flyer:

| Item | Detail |
|---|---|
| Hero image | 1200 x 800, with the title on it, from the approved flyer |
| ON24 subtitle | Exactly as sent at C7 |
| Body copy | The page text with real formatting (bullets, bold, color), so it doesn't land as one flat block |
| KOL bio | The version the KOL approved on the flyer |
| Headshot | Link to the approved headshot in the HubSpot image library |
| KOL contact | Email and LinkedIn for the speaker bio |

Operations confirms receipt; the [ON24 skill](../../lumenis-on24/SKILL.md) covers building the page. A missing item blocks the page step that needs it, not the rest.

## L1 Pre-flight (EJ, T-1)

Run every check against the live systems and record **pass**, **fail** with the owner, or **blocked**. Report it in the webinar's Smartsheet row and to Nicholas.

| # | Check | Pass when |
|---|---|---|
| 1 | Registration page | Live, correct title, date, live start and time zone; speaker bio and photo right; a test registration works |
| 2 | Form | Every required field required; button in brand color |
| 3 | Console CTA | Points to the right destination with the right tracking link, and the link opens |
| 4 | Slides | Final deck uploaded; no duplicated slides; videos play |
| 5 | ON24 emails | All five set; the 2-hour reminder is scheduled from the confirmed live start |
| 6 | Presenter links | In the tech check invite (D1) for the KOL and host, and they're the presenter link, not the attendee link |
| 7 | Tech check | On the KOL's, host's and EJ's calendars for the confirmed time |
| 8 | HubSpot segments | Registered segment is filling; Attended segment exists |
| 9 | Workflow | On (a person turned it on at D9), enrollment on this event ID, branches on this event ID |
| 10 | Em2 | Sent or scheduled, and its email check passed |
| 11 | Night-of plan | Who runs the country fix and the import after the show, and the workflow's run time |

Fails are fixed by their owner before the tech check. A blocked or failing item that can't be fixed in time goes to Nicholas, who decides whether to go live with it.
