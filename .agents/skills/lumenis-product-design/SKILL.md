# Brand system design

Resolve which brand system the piece uses: Lumenis Corporate, OptiLIGHT or OptiLIFT. Use the one the requester names; infer it only when unambiguous (a piece about one of these products uses that product's system, a piece that speaks as Lumenis the company uses Lumenis Corporate) and otherwise ask. Read [the design entry point](../../../assets/design-system/README.md), then only the selected system's entry file and the references the step needs.

The three systems are separate brand books for different purposes, not layers. Never combine tokens, palettes, type treatments, motifs, logos or components across them, and do not treat a difference between systems as a conflict to resolve. Other Lumenis products have no system here; ask for their brand guidance instead of borrowing one.

Resolve output format before selecting rules; do not infer indication, market grouping or CRM routing from design copy. Use image-library instructions for imagery and hosted links, checking allowedBrands against the selected system. Treat KOL photos as candidates until verified and claim evidence status as distinct from marketing approval. Read the linked page/form or email implementation procedure for the actual medium. Keep output external to Git and inspect the rendered result before delivery.
